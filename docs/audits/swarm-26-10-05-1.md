## §2796 — Bridge health states surfaced distinctly in-app and on the watch (2026-10-05)
- **Branch**: `feature/2796-bridge-health-states`
- **Agent (model)**: swarm-2796, claude-sonnet-5-5 / high, native subagent (impl-worker), one rework round
- **Roadmap session**: b5cff765-bec2-408d-8855-10fbb9d5cf79
- **Debrief**: `docs/debrief/2796-bridge-health-states-debrief.md`

### What shipped
- `Sources/ApexGaugeCore/Providers/Claude/ClaudeBridgeFetcher.swift`: `ClaudeBridgeState` (`iCloudUnavailable`, `noCapture`, `noWindows`) with shared title/detail/watch copy; `ClaudeBridgeReading`; `read()`. `fetchUsage()` returns an empty-window snapshot carrying the state instead of throwing `notConfigured`. An unreadable or newer-version file still throws.
- `Sources/ApexGaugeCore/Snapshot.swift`: optional, additive `ProviderSnapshot.bridgeState` with a lenient decoder (an unknown future value decodes to nil); `carryingForward(from:)` keeps the previous windows when a read reports a bridge state and no windows.
- `App/ViewModels/UsageViewModel.swift`: both refresh paths call `carryingForward`.
- `App/Views/Components/ProviderCardView.swift`: actionable banner whenever a bridge state is set, above any windows; freshness label kept when a capture exists.
- `App/Views/Settings/ClaudeSettingsView.swift`: bridge row now uses the same `read()`, so Settings and the card cannot disagree.
- `Watch/ContentView.swift`: bridge text ("Bridge idle" etc.) whenever a state is set; "Waiting for iPhone…" now means only "no snapshot received".
- `Tests/ApexGaugeCoreTests/ClaudeBridgeFetcherTests.swift`: state tests, copy tests, Codable compatibility in both directions, and the carry-forward rule.

### Coordinator review findings
- Spec bullets 1–3 met. Bullet 4 (the Pro/Max case) is met only as far as the data allows: the Mac helper writes nothing when `rate_limits` is absent, so "plan unmet", "helper never installed" and "Claude Code not run" are one missing file on the phone. They share `noCapture`, whose copy names all three. Verified in `Scripts/apexgauge-bridge.swift` and `README.md`. Filed §4811 for a helper status file that would separate them.
- **Regression found in the first submission and sent back**: returning a successful empty snapshot dropped the last-known Claude figures on any transient bridge failure, where the old error path kept them. Fixed by `carryingForward(from:)` with unit tests; re-reviewed.
- Wire compatibility: `bridgeState` is optional and additive, `UsageSnapshot.version` is not bumped, and unknown values decode to nil, so an old watch with a new phone (and the reverse) degrades to today's behaviour. Covered by tests.
- The complication target is untouched and still sees empty windows as before.
- No new files, so no project-file change; the project uses synchronized groups.
